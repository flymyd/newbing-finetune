# 执行计划：2023 New Bing / Sydney 原始对话档案

版本：v1.2，2026-11-05。状态：**用户已恢复 active goal，授权按 v1.2 执行**。最终交付为 ShareGPT 纯文本多轮对话。目录已有历史执行产物；用户恢复 goal 后在现有结果上继续，不重复已完成工作。以下为阶段验收规格，实际完成情况须按 PROGRESS、原始证据和报告复核；已知实现缺口见 [文档核查](DOCUMENT_AUDIT.md)。

## 1. 目标、范围与交付定义

目标是在有限、可恢复的采集过程中，尽可能增加真实历史 Bing 对话覆盖，优先早期 Sydney，最终交付 **ShareGPT 格式的纯文本多轮对话微调数据集**。每条至少两轮完整问答；具体字段、文本投影和验收以 [ShareGPT 输出规范](SHAREGPT_EXPORT.md) 为准。本次不训练模型。

时间优先级：

| 优先级 | 发现窗口 | 用法 |
| --- | --- | --- |
| A | 2023-02-07 至 2023-02-16 | 核心早期窗口 |
| B | 2023-02-17 至 2023-02-28 | 调整过渡期，独立标记 |
| C | 2023-03-01 至 2023-04-30 | 后续补充 |
| D | 其余 2023 | 按早期资料引用链/高价值线索定向补充 |
| U | 日期不足 | 归档保留，不强行放入 A |

窗口按来源原始时间线处理，数据库统一 UTC，同时保存原始时区与精度；报告用 Asia/Shanghai。窗口不意味着精确后端版本。2023 年 2 月 17 日限轮公告提供研究分界依据：[微软公告](https://blogs.bing.com/search/2023/2/The-new-Bing-Edge-Updates-to-Chat/)。对日期晚于窗口的转发，允许根据证据关联早期原始对话。

最终交付：

- 带原始证据、来源清单及获取状态的本地档案；原图保留字节，不被缩图替换。
- 统一结构的对话 JSONL、逐消息证据、日期依据、截断/质量/来源标记。
- 相对已知基线的新增报告，而非把多个重叠集合直接相加。
- ShareGPT 纯文本多轮 train/val/test JSON 数组文件；按 early_strict、early_probable、later_supplement 分层，配来源 sidecar 和排除理由。内部 `messages/parts` JSONL 仅作档案，不充当最终 ShareGPT 成品。
- 覆盖率、质量、失败、资源使用与复现报告，以及后续值得继续追的线索。
- 实现代码、依赖锁、配置快照、可恢复任务状态、离线测试与操作说明。

不在默认范围：实际微调、合成扩写、翻译扩充、虚构 CoT、全网视频下载、私有聊天记录、向作者发送消息、公开发布数据、全量下载 Reddit 全球月度 dump。

## 2. 总体架构与目录

采用单机 Python CLI；SQLite 存元数据、任务和唯一约束，原始 JSON/HTML/图片用文件存储，内部派生数据用 JSONL，最终 ShareGPT 主文件用 UTF-8 JSON 数组。无需在线服务。

```text
config/                    # 已提供的规划默认值，执行时读取并验证
schemas/                   # 已提供的 ShareGPT 样本/文件结构约束
prompts/                   # 已提供的提示词草案，P4 校准后冻结版本
docs/                      # 本计划、数据约定、手册、状态
research/                  # 已核实来源与历史限制
src/newbing/               # P1 起实现
tests/fixtures/            # 小型离线页面/相册/模型响应样例
data/raw/{hf,web,reddit}/  # 不改写的输入证据，gitignored
data/assets/sha256/        # 原始媒体文件，内容寻址
data/derived/crops/        # 转写裁片、缩略图及坐标映射
data/processed/            # 标准对话、分类与去重关系
data/review/               # 可离线打开的证据对照 HTML/JSON
state/archive.sqlite      # schema 版本、任务、manifest、调用计数
runs/<run_id>/             # resolved config、事件、调用、批次指标
reports/                   # 阶段/覆盖/质量/交付报告
exports/<release_id>/      # sharegpt/<tier>/{train,val,test}.json、archive 和 sidecar
```

上述运行目录及部分 CLI 已存在；目录存在不代表相应阶段通过。命令表是目标合约，实际参数与未实现能力见 RUNBOOK 和 DOCUMENT_AUDIT；实际运行命令和结果持续记录在 PROGRESS 与 reports。

## 3. 阶段与验收

### P0：执行启动、配置与模型兼容性

前提：用户在本次审阅后明确授权执行；以最新指令为准。恢复前核查已有 P0 证据，配置和能力未变化时不为重做阶段而重复消耗请求。

任务：

1. 重读文档和状态，记录用户新约束，生成 run_id 与 resolved config；检查磁盘、Python/uv、配置和凭据存在性，不输出凭据。
2. 用极小请求确认指定端点的文本 Responses 能力；用本地生成的非历史测试图片确认视觉输入；确认多图输入、结构化输出、usage、超时与响应状态。
3. 探测最多 12 次 HTTP 请求，不能借探测触发批量采集。请求体、处理方式与降级见 RESOURCES。
4. 保存 capabilities 与每次探测结果，建立统一重试、用量账本和凭据脱敏规则。

验收：指定模型的文本和视觉均实际成功；结构化输出可用，或有普通 JSON + 本地校验的明确回退；所有失败有状态。若模型不可用，先继续非模型归档工作，不切供应商；在 PROGRESS 中列出模型阶段依赖阻塞。

产物：`reports/P0-capabilities.md`、`runs/<id>/capabilities.json`、环境版本记录。不把官方协议支持等同于第三方端点已支持。

### P1：最小可恢复采集骨架

任务：

1. 建立 uv 项目、入口 CLI、配置加载/校验、SQLite migration、来源/资源/任务表。
2. 实现 `doctor`、`status`、任务 lease、原子文件写入、下载器、错误分类、Responses 客户端及内容缓存。
3. 实现 JSONL 导入/导出与基础媒体解析。下载器验证响应 MIME 与解码，防止 HTML 错误页被当图片；相册元数据保持顺序。
4. 建立关键离线 fixture 和测试；实现 `--dry-run`，显示将处理的任务及资源，不发模型请求。实现时同时校验 ShareGPT schema 与多轮语义规则，避免最后才发现输出格式不匹配。

验收：同一 fixture 重跑不增加重复数据；中断/过期 lease 可恢复；无效图、429/5xx、401/403、模型 incomplete/refusal 各走正确分支；配置上限确实拦截派发；离线测试通过。未实测的网络行为不得报告为已通过。

产物：可运行 CLI、schema v1、测试、`reports/P1-foundation.md`。

### P2：固定已有基线并优先保存作者存档

任务：

1. 从 config/sources.toml 固定两个 HF revision，下载 JSONL、README/许可说明与清单；导入记录及可用原图，记录每文件哈希。
2. 保留两套原始行与 origin 关系，识别其中相同来源/截图/会话；不能相加计算独立会话。
3. 保存 Janus 2023-02 的页面与媒体清单，随后保存 3–4 月；这些小型存档可能失效，原始保存先于耗时模型处理。后续月份此时只作原始归档，不抢占早期转写优先级。
4. 收录 Bing moments、LessWrong、Willison 页面及引用线索；正文/评论中的现成原文直接归档，不必全部 OCR。

验收：每个基线文件可回溯到 repo/revision/path；引用图片全部有终态（成功/缺失/失败待补）；基线原始行数与研究快照差异有解释；作者存档媒体逐项列出，未误称全部为 Bing。

产物：基线 provenance、资产清单、`reports/P2-baseline.md`。优先复用已有转写，针对抽样错误和未转写部分重做，不将所有旧图无差别重复推理。

### P3：Reddit 历史发现与多来源试采

任务：

1. 按资源手册复测 Arctic Shift。在线失败时切离线 subreddit dump；只选择相关版块文件，流式解压筛时间，不整包全球下载。
2. 覆盖 r/bing、r/BINGChat 的 A/B 窗口帖子；相关小社区不以标题关键词硬过滤。r/ChatGPT、r/singularity 用宽松文本/标题关键词召回；r/freesydney 按社区实际存在时期补充，不要求其在核心期有数据。
3. 解析帖子、评论、gallery、crosspost、正文 Markdown/HTML 图片、Imgur 相册及外链；保留评论上下文，排除明显机器人模板作为候选而不删除原始记录。
4. 如果不能历史枚举，转入搜索发现 + 已有 ID + 引用链模式；标记 coverage=partial，不能把结果称为全量。
5. 准备目标 500 个去重后的新候选组（帖子或相册为组，不按截图计数）。目标配额 r/bing 200、r/BINGChat 50、r/ChatGPT 100、作者存档/网页 100、freesydney/singularity 50。某层不足时记录并把剩余额度补到可用的早期层。优先追完整相册、续帖和上下文；分类不因单图仅有一轮而提前丢掉可补全线索。

验收：先剔除与基线完全相同来源/资产的候选；所有试采候选有采集状态和时间证据。500 是试点目标，不是硬造数据的指标；可达来源耗尽时按实际数量验收并报告不足。至少测出来源可达率、图片下载率、原文候选数和新颖率的分母。

产物：试点 manifest、下载结果、发现链、`reports/P3-pilot-discovery.md`。

### P4：分类、忠实转写与小样本校准

任务：

1. 用提示词草案先处理 50 个多样样本：含 Bing、其他模型、梗图、纯文本、移动端、长图和日期不明。尽量从 P3 获取；不足用基线补充，报告样本构成。
2. 分类只排除明确无关内容；疑似 Bing、日期不足、真实性不足进入 uncertain。分类模型自报置信度仅作排序，不当作准确率。
3. 对 Bing 和有希望的 uncertain 做逐图忠实转写，按相册/帖子组提供上下文；长图分块并保留原图坐标映射。大图分组时保留边界重叠，最终拼接有证据。
4. 对照原图检查 50 个样本并记录检查者类型；至少 10 个检查否定样本防漏检。用户未参与则 human_status=pending，不宣称人工标注金标准。
5. 校准通过后冻结 prompt/schema/预处理版本，完成剩余试点；错误涉及旧版本时只失效受影响缓存，不整库重跑。

验收：离线 schema 检查全部通过；校准中无已知凭空补写、角色颠倒、重叠重复的严重错误遗留；疑难不强过。参考原图的质量检查至少 50 组（不足则全检），模型独立调用的一致性检查与人工审核分别统计。

自动流转条件：严重问题已修复或移入隔离队列，模型/流程检查通过即可继续 P5；不要求用户立刻审图。高质量“人工验证集”必须等真人验证后才标为 human_verified。

产物：分类/转写、校准报告、对照审阅页、`reports/P4-pilot-quality.md`。

### P5：对话重建、跨来源去重与版本归因

任务：

1. 消除同一对话相邻截图的重叠消息。仅在原图顺序、重复段或链接证据支持时拼接跨帖对话。
2. 建立 exact_asset、repost、same_conversation、partial_overlap、text_near_duplicate 等关系，保留所有原始证据和独有上下文。
3. 精确图片去重自动执行；近似匹配先生成候选并核验。短套话不得导致两个无关对话被合并。
4. 独立记录发帖/会话/存档时间、Bing 版本外观、模式、角色扮演/提示注入上下文；对 2 月 17 日附近与晚转贴案例保留不确定性。
5. 现有 HF train/test 的标签只作上游元数据；本项目在最终去重关系上重新形成 split，不能直接拼接后沿用。
6. 父会话与所有 derived_from 片段显式建立 lineage 和防泄漏关系；不能只靠共享图片分组。父内容、角色、证据、parts 投影或裁切范围改变，派生版本和核验失效，不沿用旧 pass。

验收：对话每条消息有原始证据；原始部分内容仍可恢复；无缺失用户问题的“修复生成”；所有接受的重复关系可解释，精确重复资产不存在双份无关联记录。

产物：统一 corpus、来源/资产关系、duplicate clusters、`reports/P5-reconstruction.md`。

### P6：按收益扩展采集

任务：

1. 先完成 A/B 可达来源枚举，再扩 C，最后 D 定向线索；分类/转写队列始终优先 A，再 B，再未知但有早期证据的候选。
2. 每批默认 200 个新候选组，重复 P3–P5。按新增有效会话率、早期证据率、符合 ShareGPT 多轮门槛的会话率、完整问答数与资源开销决定下批来源；不只依赖点赞数、情绪关键词或热门案例。原始新增量与最终多轮可用量分开统计。
3. 避免只采争吵/示爱/越狱案例：保留普通信息问答、代码、创作和正常闲聊，统计它们在不同来源中的分布。发现层随机/时间分层抽样与高价值线索分开标记。
4. 对失效媒体用已知具体 URL 查公开存档和转载，最多两条替代路径；保持负结果清单。视频转写暂不启用，除非用户后续扩展范围。
5. 每批更新覆盖矩阵与收益，不因一个源失败暂停其他源。

停止某来源的条件：日期分页/文件已耗尽；或连续 3 批各 200 组（最后不足全处理）新增任意时期独立有效会话率 <5%，且 A 窗口新增率 <2%；或访问路径达到尝试上限。对非随机搜索结果只能叫“发现收益降低”，不能推断该平台已无更多数据。全局上限见 config/pipeline.toml。

验收：每个启用来源有 exhausted / diminishing_returns / unavailable / resource_limited 的有据状态；所有已接受候选完成处理或进入明确隔离状态；没有无故遗留的运行中任务。

产物：扩展 corpus、资源与收益曲线、`reports/P6-coverage.md`。

### P7：ShareGPT 纯文本多轮导出与质量验收

任务：

1. 内部档案保存 `archive/conversations.all.jsonl`；最终按 `sharegpt/<tier>/{train,val,test}.json` 导出 UTF-8 JSON 数组。每条仅 `id` 和 `conversations`，内层严格为 `from/value`，角色仅 human/gpt，value 为非空字符串；完整例子见输出规范。额外 JSONL 只在显式启用时提供同结构副本。
2. 每条至少两轮完整真实问答（4 条消息），human 开头、gpt 结尾、严格交替；优先保留完整连续会话。单轮/孤立回复只归档；不拼接无关片段、不补造 user、不按每条回复重复生成前缀。缺头/缺尾可按规范提取有独立上下文的连续多轮片段，但带 gap/截取说明且不进入最严格集。
3. 按输出规范逐类型投影为纯文本：保留正文、emoji、代码和 Markdown 表格；去除 UI/搜索状态/建议按钮；图片依赖、角色不明、不可读、缺失工具结果导致不自足的片段隔离。不能把图片描述、隐藏 system 或 CoT 合成进文本。引用、真实拒答与 UI 提示分别处理并记录变换。
4. 去重关系闭包形成 split_group，固定 seed 按组划分 80/10/10；近重复存疑关系为防泄漏可同组，但不能据此合并文本。大簇导致比例偏差时报告，不拆簇凑比例。
5. 全量校验 ShareGPT schema、多轮语义、纯文本投影、证据存在性、日期字段一致性、明显 UI 残留、异常重复率和训练泄漏；对分层样本开展最终质量检查，另出人工待审页。提供可选训练框架字段映射说明，不安装或启动训练框架。

验收：最终训练文件 100% 满足 ShareGPT 结构、至少两轮、人机交替和字符串约束；无单轮或多模态字段混入，全部 tier 无已知未解决转写错误、缺失必要上下文或无法定位证据的例子；train/val/test 的已知关联簇交叉为 0；每个样本 id 可唯一关联 provenance/transform/split sidecar；最严格 early_strict 不含日期未知/仅凭风格推断或上下文缺口样本。未人工审阅的数据明确是自动检查候选。

产物：导出文件、schema、排除理由、逐文件哈希、dataset card、`reports/P7-quality.md`。

### P8：可复现交付与后续建议

任务：清理过期运行任务，验证重跑/恢复路径，生成产物索引和覆盖报告，更新 README 与 PROGRESS；不清理或覆盖用户需要的原始数据。

验收：以下终态条件全部有证据，不以数量目标替代：

- [ ] P0–P7 的实际通过/降级/阻塞情况明确，目标模型能力实测可追溯。
- [ ] 至少已有集中集的可达部分完成归档并明确缺失清单；新增资料以去重后数量报告，可为零，不虚报。
- [ ] 启用的来源均有终态、范围和覆盖限制；资源截止导致未遍历的来源单列。
- [ ] 原始证据、标准对话、ShareGPT 纯文本多轮训练候选、审阅队列、split 和来源说明能在本机打开；成品文件与独立 sidecar 可关联。
- [ ] 测试与数据验收通过；未解决样本从严格训练集隔离并附原因。
- [ ] 至少 1 条仅是非空交付的必要条件，不替代 P0–P7 的范围、覆盖与质量验收。全部 tier 合计至少有 1 条真正合格的 ShareGPT 多轮样本；若合计为 0，只交付缺口报告，不把最终数据集目标标记为完成。单个 tier/split 可为空并解释原因。

## 4. 资源与执行边界

默认上限是供审阅的工程边界，不是已知端点额度；用户后续指令可覆盖：候选组 20,000、模型 HTTP 尝试 20,000、报告 usage 的总 token 30,000,000、下载响应字节 20 GiB、源站页面请求 50,000。超限停止对应派发并整理现有数据，不能自动扩额。

初始模型并发 2，上限 6；下载每主机并发 2，初始每主机每秒 1 请求。具体值见配置。单次运行不以墙钟时间作为完整性指标，后台无人值守不靠另建自动化：用户启动 goal 后按检查点持续执行。

费用单价、网关 QPS/TPM、视觉大小限制、模型上下文均未知，P0 记录实测，不能套用官方同名模型价格。无法获取 usage 时以严格请求/输出上限、已发送字节计数兜底，并明确 token 预算不能精确强制。

## 5. 主要风险与处理

| 风险 | 可观察信号 | 处理 |
| --- | --- | --- |
| Reddit 历史枚举失败 | API 403、dump 不可达 | 切定向文件/引用链/搜索；标 partial coverage |
| 旧图失效 | 404/占位图/权限页 | 查具体 URL 的公开存档/转载，保留失败与已存文本 |
| 新数据大量重复 | 新颖率下降 | 多层去重与来源收益调度，按条件停止该来源 |
| 转写编造或失真 | 原图对不上、缺失上下文被补写 | 忠实转写提示、证据坐标、分块核验、隔离不确定样本 |
| 模型拒绝或协议不兼容 | refusal、400、incomplete | 正确分类、有限降级，不无限绕过，不删原始记录 |
| 历史与模拟人格混杂 | 后期 roleplay、自称 Sydney | 产品/时期/提示上下文分标，严格集独立 |
| 质量只靠同模型自评 | 两次模型一致但原图不符 | 对照原图检查、人工待审标签，不夸大金标准 |
| 源许可不清楚 | 聚合集许可与截图权利不同 | 保存来源与权利说明，内部交付不自动公开发布 |

## 6. 后续变更规则

修复解析器、添加现有来源镜像、调整低风险批次大小、在上限内切换采集路径，可自主进行并记录。提高总预算、更换模型供应商、扩大到私有资料/视频批量处理、公开发布、实际训练，需用户进一步明确指令。计划里其余常规验收不构成额外批准流程。
